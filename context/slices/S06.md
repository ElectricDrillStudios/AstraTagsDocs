Verified distinctions that later slices must preserve:

- `Tags` exposes the actual stored mutable set; a fresh set/copy on every getter call cannot retain header edits
- GameObject header injection calls `GetComponent<ITagged>()` on each selected GameObject, skips individual component headers and requires a non-null set. The prefab index instead calls `GetComponentsInChildren<ITagged>(true)`
- Type discovery filters abstract/interface/generic-definition types and accepts ScriptableObjects/components. The asset reader uses the main asset, not an enumeration of sub-assets or arbitrary nested fields
- The scene path reads direct `GameTagSO` asset dependencies only when **Scan Closed Scenes** is on (default off). It does not open scenes, inspect live scene objects or establish per-object `ITagged` usage; other serialized tag references can contribute
- Incremental updates restrict paths to `Assets/`; initial type scans use `AssetDatabase.FindAssets`. The guide keeps examples under Assets and does not promise identical package-path update coverage
- Import processing updates the index; header edits are not a synchronous index rebuild. The documented saved-asset check offers **Rebuild Index**, distinct from rebuilding the registry

These are source findings and usage boundaries, not executed Unity tests. No private package files were modified or copied into this repository.
