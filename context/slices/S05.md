Implementation findings affecting usage:

- `Contains` walks upward from owned tags; set queries evaluate each query entry in that direction. One child can satisfy several ancestor requirements. Exact membership, set algebra and equality use literal references
- Null/empty set queries produce false/true/true for Any/All/None. Null single-tag queries produce false for Contains/ContainsExact/HasAny and true for HasNone. Single-tag/set HasAny/HasNone and single-tag/sequence constructors need casts for a null literal
- `MoveBefore(tag, tag)` moves that entry to the end, as does an absent target. The direct struct enumerator and interface list enumerators do not have identical mutation behavior; guidance requires finishing iteration before mutation
- Normalization is lazy after deserialization, preserving first occurrences and order. `OnBeforeSerialize` does nothing; `Tags` exposes a live read-only interface rather than a snapshot
- **F07:** `ExceptWith` iterates `other._tags` while removing entries from the receiver. With the same non-empty set on both sides, the first removal changes that enumerated list and a subsequent enumerator advance throws `InvalidOperationException`. The guide prescribes `Clear()` or a separate copy; package-side regression/fix remains outstanding
- **F08:** registry mask construction walks at most `Count + 1` nodes. With a four-node chain and only its leaf/root registered (`Count == 2`), the root is beyond the mask walk even though both stored/query tags are registered; no missing-tag fallback is selected. The guide requires complete ancestor registration and records the separate 64-node fallback guard. Package-side reproduction/fix remains outstanding; S15/S19 must retain this qualification

No package code was modified. F07/F08 are source findings, not executed Unity reproductions or passing regression tests.
