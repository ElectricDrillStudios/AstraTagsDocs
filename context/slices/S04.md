Verified distinctions that affect the procedure:

- The default runtime resource key is `AstraTags/TagRegistry`; **Editor Registry** is a GUID-backed editor selection and does not assign `Active`
- The Tag Manager prefers the configured editor registry, then directly loads the default resource, then offers creation at `Assets/Resources/AstraTags/TagRegistry.asset`. Its rebuild result shows the status line; the registry Inspector also shows naming warnings
- Project reconciliation collects tags in ordinal full-path order and saves only a changed serialized list. Its unchanged-list branch does not force a runtime rebuild. `TagRegistry.Rebuild()` only rebuilds derived data from the existing list; editor structure notifications mark those lookups stale without reconciling membership
- `Active` caches the first resource result, including null. Assigning null also pins it; only the editor reload/transition hooks release the latch. Explicit initialization must run after entering Play mode and before consumers, rather than relying on an edit-mode assignment
- Signature input is count plus ordered IDs and parent IDs, not a rebuild counter or a direct hash of names. Lookup dictionaries are case-sensitive; missing entries return null, while `IndexOf` returns -1. The runtime build ignores null/duplicate tag references without rewriting the serialized list
- `TagRegistryBuildResult` is public but its result properties are internal at this revision. S04 describes the UI result without claiming those properties are a public extension API; coverage flags this for S16
