Source findings that change user guidance:

- `TagNamingPolicy.Validate` rejects blank names, dots and surrounding whitespace. Inspector rename and Tag Manager prompts trim before validation; internal whitespace is accepted without an identifier warning. A leading digit or other punctuation produces a non-blocking advisory. `ValidateInHierarchy` checks sibling/root uniqueness with `OrdinalIgnoreCase`
- Direct Project-window actions and `GameTagSO.OnValidate` do not provide the same enforcement as checked creation/rename actions. `OnValidate` emits syntax warnings without rewriting names or checking sibling collisions; the Inspector's parent setter also skips the naming policy
- `ShowParentMenu` and `SetParent` call the cycle predicate on the candidate parent (`candidate.WouldCycleWithParent(target)` / `parent.WouldCycleWithParent(tag)`), reversing the intended direction. An existing ancestor can be omitted, while a descendant can be offered; `GameTagSO.OnValidate` then detects a cyclic assignment and clears the parent. The guide gives a root-first workaround for selecting an omitted ancestor and warns against selecting descendants. This is source inspection, not an executed GUI reproduction; state F05 tracks the package correction
- `SetParent` does not check destination sibling-name collisions. The guide requires checking the destination before reparenting; state F06 tracks the enforcement gap
